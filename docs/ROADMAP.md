# Product Direction

This roadmap records direction, not a completion ledger. Current actionable external blockers live in [TASKS.md](./TASKS.md); historical release claims live in [V1_LAUNCH_EVIDENCE.md](./V1_LAUNCH_EVIDENCE.md).

## 1. Controlled Image-Series Production

Keep one user-visible path from brief and blueprint selection through durable queue execution, candidate comparison, structured review, human approval, and path-safe delivery. Improve real-provider capability only behind explicit cost authority, immutable request identity, and no automatic replay.

## 2. Trustworthy Scientific Figures

Keep source evidence, approved figure specification, deterministic SVG authority, independent semantic/visual review, bounded repair, human Gate 1/Gate 2, and evidence-backed delivery as one coherent workflow. Scientific meaning remains human-authorized; OCR-heavy and observation-like inputs fail closed until admitted with evidence.

## 3. Desktop Quality

Prioritize interruption recovery, Chinese file handling, accessibility, export reliability, large-gallery responsiveness, and clear provider state. Prefer native UI Automation and operator acceptance for real desktop behavior; avoid replacing them with source-token tests.

## 4. Architecture Restraint

Scenario labels remain profiles, not platforms. Do not revive Pack, WorkflowPackage, ArtifactPlanning, ToolAdapter/Operator runtime, remote workflow, module registry, or machine task queue without two real product consumers and a measured failure that the existing product path cannot solve.

## 5. Triggered Future Work

The following are not active backlog items:

- OCR or stronger scholarly extraction when an admitted source class requires it.
- New provider operations when a user-visible workflow and explicit authority contract exist.
- New scenario-specific behavior when it cannot be represented by existing profile and delivery-category data.
- A fresh release/live/hardware evidence run when the acceptance basis materially changes.

Repository verification proves only the checked code and contracts. It does not create paid-provider, human, hardware, or field acceptance.
